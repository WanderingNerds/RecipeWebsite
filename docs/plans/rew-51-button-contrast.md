## Jira issue
[REW-51: Low-contrast button text on View, Edit, and Import Recipe buttons](https://wanderingnerds.atlassian.net/browse/REW-51) (Bug, Medium priority, labels: `accessibility`, `ui-bug`)

## Confluence page
[Potluck Design System - Brand and UI Foundation](https://wanderingnerds.atlassian.net/wiki/spaces/Recipe/pages/17235969/Potluck+Design+System+-+Brand+and+UI+Foundation) — updated with a REW-51 section (this plan's summary + link) and a correction to the "Buttons" implementation-status row.

## Summary
The View, Edit, and Import Recipe buttons (and every other button/link sharing the same `.btn-outline` CSS class) render near-invisible text because `.btn-outline` sets `color: var(--potluck-oat-milk)` (`#f4ebdd`, cream) on a transparent background, which is a treatment designed for the dark olive hero/navbar. In practice `.btn-outline` is used almost everywhere else — recipe cards, forms, modals — on light `--potluck-paper`/`--potluck-vanilla` surfaces (`#fffaf1` / `#faf5ea`), producing a measured contrast ratio of roughly **1.09–1.14 : 1** (cream-on-cream), far below the WCAG AA minimum of 4.5:1. This is a known, previously-flagged drift item: the Confluence design-system page already documents `.btn-outline` as a "non-spec extension... plans to recolor it to match `.btn-secondary` (ink/divider) rather than remove it, to avoid large view-file churn." This plan executes that recolor. The one legitimate dark-background usage (the navbar Logout link) is moved to the purpose-built `.btn-outline-light` class (already used correctly in the homepage hero) so it keeps its current, already-passing cream-on-olive contrast instead of becoming invisible under the new ink-on-light styling.

## Open questions / assumptions
- **Scope beyond the 3 named buttons:** The ticket names only View, Edit, and Import Recipe, but a full repo grep confirms `.btn-outline` is used in 17 places across 9 files, and 16 of those 17 are on light backgrounds with the identical bug (Cancel/Save as draft in `edit.ejs`, Edit Recipe in `view.ejs`/`public-view.ejs`, Login in `public-view.ejs`, Clear Filters x2 and View/Edit in `index.ejs`, Browse all recipes x2 in `search.ejs`, Save as Draft in `import.ejs` and `new.ejs`, Open Full Import Page in `import-modal.ejs`). Because the fix is a single shared CSS class, there is no cheaper way to fix only the 3 named buttons without either (a) forking a new class just for those 3, leaving 13 other buttons still broken, or (b) fixing the shared class, which fixes all 16 at once. **Assumption: fix the shared `.btn-outline` class**, which resolves the ticket's 3 named buttons and the other 13 identical failures in the same change, consistent with the design system page's already-stated direction. Flagging this explicitly in case the user wants a narrower, per-button override instead — but recommend against it, since it would leave known WCAG failures live on identically-styled buttons.
- **Navbar Logout button:** Not mentioned in the ticket and not currently broken (cream-on-dark-olive already passes at ~6:1). Recoloring `.btn-outline` at the class level would break it (ink-on-dark-olive). Assumption: retarget just this one link to the existing `.btn-outline-light` class rather than leaving `.btn-outline` untouched — this is a 1-line, zero-visual-change swap, not a new design decision.
- **`import.ejs` "Start Over" button** (line 140) already has an inline `style="color: var(--text-muted);"` override that takes precedence over the class and is not part of the reported bug (gray text, already roughly AA-passing on light backgrounds). Left out of required scope; flagged as an optional cleanup the Developer may fold in for consistency (remove the now-redundant inline override so it inherits the fixed `.btn-outline` ink color) but not required for acceptance.
- No clarification needed from the user beyond the above — proceeding per Auto Mode guidance since the fix is low-risk, presentation-only, and already directionally endorsed in the design-system doc.
